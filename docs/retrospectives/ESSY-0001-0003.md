# ESSY-0001–0003 Retrospective — Subtitle Timing

## The problem (found by human audience-experience review)

Structural subtitle QA (text preservation, overlaps, orphans, 2-line limit,
minimum duration) passed for ESSY-0001/0002/0003, yet burned subtitles were
perceptually out of sync with narration in places. A read-only timing audit
found the cause: semantic subtitle children were timed by
**character-proportional interpolation** inside parent VTT windows. Real
speech does not pace characters evenly (pauses, stress), so drift accumulated
within a block and reset at block boundaries — "first sentence aligns, later
sentences drift".

ESSY-0003 exposed the worst failure: edge-tts CLI `--write-subtitles` emitted
**one giant VTT cue for 29/32 blocks** (up to 47.6 s / ~12 sentences), so
almost the whole episode's subtitle timing was estimated, not tied to speech.

## The fix (Edge TTS WordBoundary, no new dependencies)

Edge TTS already exposes per-word timing (`WordBoundary` events, 100 ns
ticks; `boundary="WordBoundary"` in edge-tts >= 7). Architecture after the P0
fix:

- **Semantic segmentation decides WHAT text is grouped** (unchanged DP
  phrase-aware segmentation).
- **WordBoundary timing decides WHEN it is spoken**: each child cue gets
  `speechStart` = first mapped word start, `speechEnd` = last mapped word
  end, plus a per-cue `timingSource`
  (`edge-word-boundary` / `legacy-vtt` / `char-estimate`).
- Presentation lead/linger are separate policy (currently 0/0 — the
  human-validated configuration; do not tune speculatively).
- Canonical TTS integration: `scripts/generate-essy-tts.py` produces audio +
  VTT + word-timing artifact in ONE synthesis session, cache-bound by
  textSha256 + voice/rate/pitch/volume. New-generation ESSY manifests record
  `subtitleTiming.policy = "word-boundary-required"` — missing/mismatched
  word timing FAILS QA before render. Legacy episodes (0001–0003) load with
  an explicit warn/fallback, never silent.
- Timing-integrity QA: timingSource counts, word coverage ratio, fallback
  blocks/cues, cue-vs-word deltas (P50–P99/max), speech-gap residuals.
  No unvalidated perceptual threshold is enforced.

## Validation

- Controlled sample: ESSY-0003 N003 (47.6 s giant cue). Old char-share start
  drift vs actual speech: p50 = 540 ms, p95 = 1461 ms, max = 1716 ms. New
  word-boundary timing: 0 ms by construction. All 20 cues word-timed,
  coverage 1.0.
- **Human perceptual validation of the N003 sample: PASS.**
- Production-path smoke (SMOKE-ESSY-WT, N001–N003, ~72.5 s, real visual
  assembly, canonical narration master + review renderer): 30/30 cues
  word-timed, QA pass, coverage 1.0.

## Validation-tool lesson

Standalone review clips MUST rebase audio, video and subtitles to the SAME
local time origin. The first N003 sample burned global assembly timestamps
(N003 starts at 24.36 s) onto block-local audio — the sample showed a
~24 s subtitle delay that was a harness bug, not a timing bug. Rule:
`localCue = globalCue - sampleStartSec`, with assertions that no local cue
starts < 0 and the last cue ends within the sample duration.

## Scope note

This is production-pipeline validation only. No audience-level (YouTube)
validation has been performed.

## Script compression — P1 evidence (ESSY-0001–0003 audit)

**Verified patterns** (retrospective read-only audits, see
`projects/ESSY-0001/compression-review.md`, `projects/ESSY-0002/compression-review.md`,
`projects/ESSY-0003/compression-review.md`; approved scripts untouched):

- All three episodes exceed the 9-min review trigger (≈9.2 / 9.2 / 11.9 min;
  949 / 1,189 / 1,492 narration words) despite modest word counts — the
  reflective pacing (short blocks, pauses) makes every redundant sentence
  expensive in runtime.
- Recurring failure mode is **same-function adjacent blocks** and **thesis
  restatement after the point has landed** (e.g. ESSY-0003 N011+N012,
  N026+N027; ESSY-0002 N006/N007 and N009/N010; ESSY-0001 n016/n017). This is
  consistent across all three episodes, so it is treated as a verified pattern.
- Class-C structures (escalation lists, concrete contrast lists, callbacks,
  endings) were repeatedly found to be exactly where the length IS justified —
  any compression rule must protect them explicitly.

**Hypothesis (not yet verified on a new production):** applying the
compression pass at draft stage yields ~10–15% word reduction without tone
loss (est. 90–120 / 130–170 / 210–300 words for 0001/0002/0003), and ESSY-0004
can land inside 6–9 min. The ESSY-0003 before/after examples validate the
editorial rule editorially, but no compressed script has been human-approved
or rendered yet. Duration policy: 6–9 min preferred, >9 min mandatory
compression review, >10 min written justification, no hard cap.

Older episodes are NOT treated as if they followed this process; their
published masters remain as-was.

## Still-image motion comfort — RULING (P1 canonical policy, implemented)

**Why the old behavior was rejected (human review):** every still shot was
forcibly animated; direction alternated push-in/pull-out by shot-index parity;
motion completed early (~1.025 capped at~4.6 s @25 fps) and froze for
longer shots; the result felt uncomfortable / dizzying,and the PUSH/PULL
zoom-pan test clips looked like drifting/wobbling. **Geometry investigation**
(4x-supersampled zoom crop, then lanczos downscale; measured anchor residual
≈0 px) was useful diagnostically — it distinguished quantization wobble
from true anchor drift — but we deliberately chose a simpler editorial policy
rather than building a sophisticated Ken Burns engine.**

**Canonical rule (replaces the P1 "PROPOSED" section above):**
- STATIC is the default treatment for still images.
 Absence of `stillMotion` metadata = static.

- Motion **must be explicitly editorially justified** via
  `stillMotion: "slow-push"` (stable center push-in only). The numeric
  zoom default (`SLOW_PUSH_ZOOM_MAX` in `scripts/_still-motion.mjs`) is an
  implementation default, not an editorial requirement.

- No automatic alternating Ken Burns by shot index; no random motion; no
  auto-motion merely because the asset is a still image.

- `slow-pull` and `pan` are NOT approved production treatments yet.

- "Calm frame, meaningful motion."

**Production integration (this task):** policy lives in
`scripts/_still-motion.mjs` (shared `resolveStillMotion` + `stillImageFilter`);
`build-assembly-timeline.mjs` carries `stillMotion` per slot from the sourcing
plan/visual-package through `assembly-timeline.json` shots; review
(`render-lesson.mjs`) and final (`render-essay-final.mjs`) resolve the SAME shared
helper — no duplicated motion policy. Video assets are unaffectedpiris
still-image-only. Published ESSY-0001/0002/0003 masters are not re-rendered;
their historical behavior remains as-was. New canonical policy applies to
ESSY-0004+ / newly-rendered episodes. Rebuilding the legacy episodes with the
new defaults is NOT guaranteed to reproduce historical behavior and is not
bit-exact backward compatibility.
 Backward-compatible: no metadata = static.

Regression tests A–Fin `scripts/_test-subtitle-segmentation.mjs` (still-motion
block) plus a tiny static-vs-slow-push smoke (`scripts/oneoff/still-motion-policy-smoke.mjs`)
validate the policy without touching renderers or masters.

## Still-image motion comfort — audit / design record (superseded by the RULING above)

**HISTORICAL (pre-decision; retained only as the diagnosis record. The canonical policy is the RULING section above):**

**VERIFIED current implementation (audit):** every still shot receives Ken Burns
motion via `kenBurnsFilter` (`scripts/render-lesson.mjs`, identical constants
duplicated in `scripts/render-essay-final.mjs`): center-only zoom 1.000↔1.025,
±0.00018/frame (completes in ~4.6 s @25 fps, then holds for longer shots),
direction alternates by shot index parity (even = push-in, odd = pull-out). No
pan, no easing, no per-shot metadata, adjacent shots do not know each other's
motion. Review and final use the same constants (logic duplicated, one source of
parameters).

**HUMAN observation (ESSY-0001–0003 review):** conspicuous alternating
movement between adjacent stills and motion that draws attention to itself can
feel dizzying.

**PROPOSED policy (NOT enforced, NOT Production Ready):**
- Hierarchy: STATIC (default safe) → VERY SLOW PUSH-IN (subtle emphasis) →
  VERY SLOW PULL-OUT (release/context) → PAN (exceptional, only with a
  meaningful spatial destination).
- Do not alternate motion for variety; adjacent shots must not oppose.
- "Calm frame, meaningful motion": a still may stay static its whole shot;
  7–10 s duration is a sourcing heuristic, not a mandate to move.

**UNVALIDATED numeric candidates (awaiting the contact-video comparison):**
push/pull 1.000↔1.040 linear across the full shot duration; pan fixed zoom 1.08
with slow lateral drift. The current 1.025 cap completing in ~4.6 s is a
verified candidate cause of "motion then dead frame" conspicuousness.

Comparison artifact (existing assets, read-only):
`temp/motion-comfort/motion-comfort-contact-540p.mp4` (112 s, 960×540@25) —
labelled STATIC / PUSH / PULL per case (A portrait, B wide, C pan-candidate),
one CURRENT-behavior example, and BAD vs CALM adjacent-shot sequences.
